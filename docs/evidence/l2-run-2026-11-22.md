## Setup

Build inside the container (named volume nebula-ws mounted at /ws):

```
git clone https://github.com/tier4/nebula.git /ws/nebula
cd /ws/nebula && git checkout 4e02244695879e823f570f13449d95cb642cd35a
vcs import < build_depends-jazzy.repos
rosdep install --from-paths . --ignore-src -y -r --rosdistro jazzy
```

Result: 11 packages built, no errors.

## Method

- Each case starts `hesai_ros_wrapper_node` with `ros2 run`, the default param file `PandarXT32.param.yaml`, `launch_hw:=false` (offline mode, no sensor) and the case's overrides. Runner: `scripts/l2_run_case.sh`
- The node is stopped with SIGINT after 25 s. Exit code 124 means the node was still running when stopped. Exit code 250 was observed when the node aborted during startup
- While the node runs, the runner records `ros2 param dump`, and for some cases `ros2 param describe` and a `ros2 param set` attempt
- TC-RUN-004 uses a copy of the default param file with the `min_range` line removed: `grep -v '^    min_range:' PandarXT32.param.yaml`
- Every case was run 3 times. Exit code, matching log lines (timestamps removed), parameter values and set results were compared. All 3 runs were identical for all 11 cases. A first single run of all cases gave the same results

### Why calibration_file is overridden

The default param file sets `calibration_file` to `$(find-pkg-share nebula_hesai_decoders)/calibration/$(var sensor_model).csv`. These substitutions are resolved only by a launch file (`hesai_launch_all_hw.xml` loads the file with `allow_substs="true"`). With `ros2 run` the text is used as a path, and the node aborts with "No valid calibration found: Invalid Calibration File". All runs therefore pass the absolute path of `PandarXT32.csv` from the install folder.

## Details

### TC-RUN-002
- Log: "PTP transport was set to 'UDP' but PTP profile '802.1as' only supports 'L2'. Setting it to 'L2'."
- `ros2 param describe ptp_transport_type`: string, "Read only: true"
- `ros2 param set ptp_transport_type L2` from outside: "Setting parameter failed: parameter 'ptp_transport_type' cannot be set because it is read-only". The value stays UDP
- Code: hesai_ros_wrapper.cpp L240 declares the parameter with param_read_only(). L251 sets the internal config to L2. L252 calls set_parameter with L2 and does not check the result
- Inference (not traced inside rclcpp): the update at L252 fails for the same read-only reason as the external set

### TC-RUN-003
- `ros2 param describe data_port`: integer, "Read only: true", no range
- 4464 = 70000 - 65536
- Code: rclcpp returns integer parameters as int64_t (parameter_value.hpp L261-L267 in /opt/ros/jazzy/include/rclcpp/rclcpp). hesai_ros_wrapper.cpp L157 stores it in data_port, a uint16_t field (nebula_common.hpp L312)
- Not observed: with launch_hw=false no socket is opened. The hardware interface uses this field for the data socket (hesai_hw_interface.cpp L228), so with a sensor the driver would listen on 4464 (code reading)

### TC-RUN-001 and TC-RUN-005
- `ros2 param describe rotation_speed`: integer, Min 300, Max 1200, Step 300, "Additional constraints: 300, 600, 1200"
- 900 is inside the enforced range but not in the listed constraints. 360 is outside the enforced step

### TC-FOV-011
- `ros2 param describe`: cloud_min_angle and cloud_max_angle are each an integer from 0 to 360, step 1, with no rule between them

## Limits of this run
- launch_hw=false skips the hardware interface: no socket, no sensor setup, no packets. Checks that happen only there are not covered
- No point cloud is produced, so diagnostics during operation and FoV output are not observed (L3 or L4)
- The XT32 calibration file from the install folder was used, not a calibration downloaded from a sensor
